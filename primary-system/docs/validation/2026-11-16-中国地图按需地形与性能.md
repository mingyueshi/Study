# 中国地图按需地形与性能验证

日期：2026-11-16。入口：`/geography/atlas/china-3d.html`。

## 实现与边界

- 初始页面不加载全国 `china-terrain-data.js`。先显示同源概览，放大后按视口读取 4°×4°的本地详细块，共 96 块；通常显示最多 12 块、缓存最多 24 块，同时读取最多 3 块。重复请求合并，视口改变可取消旧请求。
- 点选海拔、地形定位、三级阶梯坐标作答和剖面先保留所需详细块，再用原始高程计算。读取失败时保留概览，不用概览高程计分。临时采样任务可超过通常缓存上限，结束后释放、淘汰；任务切换后迟到结果失效。
- 原始详细网格的 843942 个三角面和高程全部逐面对应，概览与详细块均保留 51482 段省界。流域、湖盆掩膜按块拼装，湖面、雪线、省份抬起与倍率继续可用。
- 干流与支流的地形切分移到生成阶段，分别烘焙概览、详细河线。浏览器拼装现成线段，不再启动时切分全国河道。输入绑定 DEM、河道、水文、湖泊与几何脚本指纹。
- 地形色阶预生成 −500—9000 米整米 Float32 查表；每个顶点直接填入颜色，避免反复构造 Color 对象，线性 RGB 与原算法相同。
- 当前引擎为 Three.js 0.180.0，已经使用 WebGL2。各省是不同几何，保留按省合并绘制以支持独立点选和抬起。省界、河线继续使用现有实例化线段接口。InstancedMesh 适用于相同几何和材质的对象，不据此承诺帧率固定翻倍，参见 [WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer)、[InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html)。

## 验证

- 源测试逐个校验 96 块的字节数、SHA-256、高程、每个原三角形只出现一次、省界总数、掩膜长度和烘焙输入指纹。
- 地理图谱 6366 项检查及水文、教学、原玩法源测试通过。
- `make test-frontend`：248 项通过，含新增颜色、局部索引替换、视口选择、并发上限、请求合并／取消、缓存淘汰、版本错误重试、页面关闭失效共 8 项。
- `manage.py test catalog.test_study_topics`：11 项通过；生成检查为 858 文件、0 差异，`git diff --check` 通过。
- Playwright 首屏确认全国详细数据全局未加载，详细块请求为 0；东北视角读取对应 12 块，没有下载西部全网格。连续切换东北、青藏高原、四川盆地、天山后缓存不超过 24 块。
- 点选与定位读原始海拔，阶梯挑战约 5140 米反馈正确；左右对照同一点都读约 1930 米。海拔柱、湖面／雪线开关、流域与剖面通过。西向东示范剖面约 2876 千米，海拔范围约 −3—5230 米。
- 主动中断详细块请求后，概览继续显示、记录不增加；重新提交可恢复。延迟返回时切换任务，旧结果不会亮灯或覆盖新反馈。
- 通过 `file://` 直接打开源页面并读取详细块、完成坐标作答；未引入 CDN、运行时外网请求或构建依赖。
- 390、820、1920、3440 像素窗口无横向溢出。8012 服务已沿用原局域网地址、完整环境和 SQLite 配置重启；实际服务首屏无全国详细 DEM，东北视角读取 12 块、保留 34 个省份模型，东北平原读数约 200 米，地球仪的 WebGL 与地形状态正常。
- 禁用 WebGL 后仍可通过坐标读取详细块，三级阶梯挑战得到约 5140 米并正确亮灯。实际服务无应用或着色器错误；局域网 HTTP 下浏览器仍提示忽略 COOP 响应头，不影响上述交互。
