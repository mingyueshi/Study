## 2. 数据结构与证据

| 模型 | 作用 |
|---|---|
| `LexiconSource` | 来源、网址、署名、代码许可、数据许可、公开依据、启停、优先级、当前版本 |
| `SourceRelease` | 固定版本、适配器版本、文件摘要、清单摘要、导入游标／状态／报告 |
| `SourceBinding` | 来源内稳定键 → 义项与读音；独立保存身份字段，避免按同形词误绑 |
| `SourceRecord` | 某版本的原始 JSON、原记录摘要、规范化字段和 JSON Pointer 证据 |
| `LexicalEntry` | 稳定 UUID、语言、词头、类型、审核状态、归并重定向 |
| `Sense` | 稳定义项、释义语言、独立人工修订、revision 与审核状态 |
| `Pronunciation` | 读音槽、音系／地区、人工修订与核对状态 |
| `EntryForm` | 来源明确的词头、别名、词形变化或字形变体，附字段路径 |
| `ContentEntryLink` | 教学卡片选定的义项、读音与来源证据；保留原关联直到人工确认 |
| `EntryMatch` | 同形词候选与人工判定；归并词头时保留全部义项和原 UUID |
| `LexiconAudit` | 来源策略、版本切换、人工修订、审核、关联和归并的操作记录 |

来源版本内一条原始记录保留为一个来源义项包；不会把混合释义自动切成未经证实的多个义项。可通过不同来源稳定键表达明确区分的义项或读音。词头不要求全局唯一，大小写折叠只用于检索；汉字扩展区和异体选择符保持原字符序列。

`raw_hash` 是原始对象的规范 JSON 摘要；`lexical_hash` 是核心语义字段摘要。`SourceRelease.checksum` 是整个导入清单的规范 JSON 摘要，不等同于磁盘文件摘要。原文件摘要另存 `source_files`。哈希用于一致性检查，不是来源真实性或使用权证明。

原始记录与审计在模型常规保存／删除和后台层面只读；直接数据库 SQL、`QuerySet.update()` 或特权脚本能绕过应用约束，因此只允许受信任维护代码使用这些入口。

## 3. 后台操作与权限

入口：`/admin/` → 基础词库。已有内容详情也会显示词库关联，要求相应词库查看权限。

- `词库编辑`：查看原文，修订义项／读音，核对同形词，维护教学关联。不能批准来源公开、发布内容、管理用户或读取私人进度。
- `词库来源与发布`：维护来源元数据与公开依据，查看并切换版本，审核词条／义项／读音。不能修改释义或用户记录。
- 超级管理员具备完整管理权限；同一工作人员确需两类职责时可以同时授予两组。

词义／读音页面同时显示当前来源文本与人工修订。填写修订依据后保存；修订 revision 加一，并撤回该项审核状态。过期页面保存会返回冲突提示，不覆盖他人的新修订。清空人工值并说明原因后，可在重新审核后使用来源值。

同形词详情和归并确认页显示双方来源、版本、义项 UUID、释义、读音及人工值；长释义只预览前 1,500 字，完整原文通过证据链接查看，每方最多最近 20 条。仅在确认属于同一词头时归并，义项不会被合并。旧词条 UUID 在新词条可公开时临时跳转，撤回后旧入口同样返回 404。判为不同词条的候选不会因重复导入重新变为待审。

候选生成按语言、检索键和类型分组；单组超过 50 个条目时跳过自动两两生成，需先专项核对。没有自动语义判断或全量去重。

```sh
  --batch-size 500 --report ../output/lexicon-validation/xinhua-stage.json
```

适配器只接受已核对的固定文件：上游提交 `8de1001aa499cd65fb97ef8712550188c0297a08`，SHA256 `1d4b4f454ce1c416d6a1ab2369d6e66c0ff99e04390172eef70790499e21ce19`。保留释义、拼音、出处、例句、缩写及原字段路径。上游新版本要先核对来源和结构，再新增适配版本或转换为通用清单，不能只替换文件绕过摘要校验。

来源的代码许可与数据内容公开依据分别记录。该成语快照没有获准公开展示，也没有被变成三万张教材卡；后续已接入的开放来源与其独立审批。

## 5. 新来源与通用导入清单

可执行的自编示例见 `lexicon/examples/interchange-v1.json`，只用于格式演示。先预演，再导入：

```sh
.venv/bin/python manage.py import_lexicon --adapter json \
  --input lexicon/examples/interchange-v1.json --dry-run
# 对真实数据完成核对后，将 --input 换为已准备的清单；去掉 --dry-run 才暂存。
```

清单主要字段：

- `schema_version: 1`，`source.code/name`，固定 `version`，标识解析规则的 `adapter`，以及 `records`。
- 每条必须有来源内稳定 `key`、`language`、`kind`（`character/word/phrase/idiom`）、`headword`、`gloss_language`、`definition`。
- `raw` 保存原始对象；`field_paths` 的 `headword/definition/pronunciation/pos/properties.*` 用 JSON Pointer 指向原文。非空读音、词性和每个扩展属性都必须有对应证据。
- `pronunciation` 提供 `value/system/region`；`forms` 可提供 `text/role/source_path`。只支持有证据的别名、词形变化和变体，不推测补齐。
- 经过人工核对的替代来源可使用 `target_sense: "现有义项UUID"`，见下一节。一般新增来源不填写，先产生独立条目和匹配候选。

`--dry-run` 验证全清单、字段路径、版本冲突和已有身份映射，完全不写库。实际导入在预验通过后分批提交，默认 500 条，最多 2,000 条。异常保留已提交游标，重新运行相同命令从断点续跑；未完成版本不可启用。相同版本、相同清单不重复写入；相同版本换内容会拒绝，必须使用新版本号。来源文件缺失记录不会删除旧证据、教材或进度。

导入报告包含缺失释义／读音、创建或复用数量、教学关联与候选数量。重复导入时创建数为 0，原版本累计数在 `version_totals`。中途失败可在后台版本页查看 `error/processed/report`；不保证失败调用产生成功格式的报告文件。清单中的公开开关不能授予权限，已有来源准入也不会被清单覆盖。

## 6. 版本启用、回退与来源替换

### 同一来源升级

1. 用同一来源 code、新 version、新完整快照导入。原有稳定 key 保留同一个义项与读音槽。
2. 后台“来源版本”选择一个完整版本，执行“查看差异并启用／回退”。查看新增、修改、缺失、未变和受影响教学关联数量，核对原始记录后填写依据。
3. 确认才切换生效指针。若期间其他人已经切换，系统拒绝旧确认页面；需重新查看差异。回退同样选择旧的完整版本，不删除新版本。
4. 在“教学词义关联”的来源变化检查中处理新版缺失／释义读音变化。关联证据不会自动改指；管理员选择新证据、相符义项和读音并说明复核依据。

命令行适用于受信任维护者，操作会留审计：

```sh
.venv/bin/python manage.py activate_lexicon RELEASE_UUID \
  --expected-current none --reason '完成内部内容核对，首次启用'
# 已有生效版本时，把 none 换为刚核对过的当前版本 UUID；回退时也需填写。
```

激活只是确认使用哪个完整版本；公开仍受来源准入与词条／义项审查限制。若该来源及义项已允许公开，启用新版会对外采用新版原文，必须在确认前核对变更；已有独立人工修订继续优先，不被新版或回退覆盖。来源策略修改与版本切换不会互相覆盖。

### 换成另一供应方／词库

1. 为新来源建立独立 code 和固定版本，保留新来源自己的许可、署名、原文和键。不要冒用旧来源的 code。
2. 把已人工确认对应的义项 UUID 写入新记录 `target_sense`。导入器校验语言、字面词头、类型与释义语言；语义是否对应仍由审查者决定。未确定的记录保持独立候选。
3. 暂存并核对后启用新来源，单独完成准入与内容审查，再停用旧来源。稳定词条／义项 UUID、人工修订和用户记录不变；来源读音槽独立保留。
4. 教学卡片原关联仍指向旧证据。逐项复核并选择新来源证据，才恢复该卡片的词典展开。旧教学讲解、故事和学习进度始终保留。

身份字段改变要使用新来源键；不能在同一个稳定键上悄悄换词头、语言或类型。现有来源映射也不能通过导入任意改绑义项。首期不提供义项拆分或不确定语义自动迁移工具。

## 7. 公开读取边界

词典公开读取同时要求：来源 `enabled/public_allowed`、完整生效版本、词条和义项审核通过。读音另需人工核对。必须填写数据许可、署名与公开依据才能通过后台开放来源；这些记录不能替代实际来源审查。

查词 JSON 列表支持 `q/language/kind`，词形与已审读音做前缀查询，每页 30 条；详情按来源优先级列出最多 100 条证据，附 `has_more`。它返回义项、读音和来源摘要，不暴露后台 raw、内部依据或用户数据。统一词典页面已在 `/dictionary/` 提供，页面义项可分页；当前没有批量导出、音频或自动补全端点。

来源停用、准入撤回或内容撤审会同时从查词、详情和教学词典展开隐藏；响应设置 `no-store`。教学展开还验证生效来源核心字段与人工选择时的证据一致，变更或缺失返回空关联等待复核，不偷偷替换教学词义。原有教学卡正文是独立内容，不因外部词库撤回而改写；若教学正文自身需要撤回，使用原有内容下架流程。
