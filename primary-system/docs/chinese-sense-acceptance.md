# 中文义项版本与教材修订保护：主控验收

日期：2026-11-02。状态：**本阶段主控验收通过。** 实施由原 GPT-6.1 SOL 会话完成；本文件由主控维护，记录设计约束和独立核验，不替代实施报告。通过范围为中文版本与学习依据机制、教材修订保护及本地升级，不包括全库中文内容审校。

## 范围与基线

依据 [基础资料规划](foundation-data-plan.md) 第3、4、7节，先实现中文义项版本、显式采用、最近一次学习记录的呈现依据以及教材词义关联保护。本轮不进行全语料入库／翻译，不扩展新学科。

主控在实施开始时以只读SQLite一致性副本记录32张业务表、313,132行的原字段摘要；其中教材词义关联306、场景词位577、场景目标577，账号、教材进度和场景进度均为0。完整原字段与逐行摘要保存在仓库根 `output/primary-system-audit/2026-11-02/chinese-control/baseline-rows.json`，权限0600，不含行正文。迁移完成后按原列重新比较，新增模型／列单独说明。

由于日常库没有真实历史进度，旧true/false、掌握、收藏、笔记和时间保护必须另用有历史记录的隔离升级样例验证。不能将空表升级通过称为全部历史数据保护已证明。

## 已发现并下发的设计问题

1. 教材关联虽然保存来源证据，但当前释义／读音读取会采用最新人工修订，缺少选用时修订快照与失效判断。
2. 教材摘要、正文、旧sections与备用词卡渲染可能绕过词库保护，必须覆盖页面、目录、搜索和API的实际出口。
3. 只有进度revision不能检测后台换中文版本。学习提交须携带并校验用户所见采用版本，不能由服务端悄悄补成最新版。
4. 收藏／笔记与学习状态共用表时，保存附注不能将旧mastered重新绑定到新词义。应区分附注修改与明确学习确认，并一致计算当前有效掌握。
5. 维护页面确认的版本与事务最终采用的版本要比较；只在保存时锁住并读取最新版，不足以证明维护者核对过该版。
6. 多slot教材不能只展示main却把全部关联记作已见。所有参与学习确认的关联必须实际展示，失效关联也要有可见说明。
7. 初版搜索／掌握汇总逐条解析关联。主控在独立副本建立306条有效教材掌握后实测：中文搜索1416次SQL、首页927次、个人页921次，约0.36–0.61秒。已改成请求内批量解析并复测，避免跨请求缓存延迟撤回，结果见下文。证据为同目录 `performance-before.json`，这些测试账号／进度仅在现已清理的 `control.sqlite3`。

## 独立验收矩阵

| 检查 | 要求与证据 |
|---|---|
| 义项身份 | 同形不同义不可共享中文版本；跨场景同目标可共享，同读音不同义不猜配 |
| 中文版本 | 采用明确证据与修订快照；确认后的正文不可原地覆盖；撤回保留正文、引用与记录 |
| 语义修改 | 纯呈现更新经确认可沿用目标；改义／换读音／换证据必须新目标，旧进度不复制 |
| 教材保护 | Sense及读音revision或实际值变化均生效；直接ORM改值不能绕过；明确重新采用后才显示新版 |
| 生命周期 | 未启用、来源撤回、义项停用、删词、源变义、回退、归并各有明确结果；失效中文不可补回 |
| 内容出口 | 词卡API、教材关联API、教材详情／列表／搜索、summary/body/sections及朗读属性不漏失效释义与音标 |
| 后台维护 | 创建、确认、采用、撤回有可用入口及权限；旧维护页面不能确认未看过的新修订 |
| 词卡保存 | 同时校验账号／游客、目标、progress revision、所见呈现；版本切换后旧页提交冲突，不静默记录新版本 |
| 教材保存 | 学习状态与附注修改区分；只收藏／记笔记不刷新掌握依据；旧依据与新义不兼容时提示复核 |
| 汇总一致 | 教材详情、个人列表、首页统计对当前掌握采用同一语义；旧mastered保留为历史声明，不计成新义掌握 |
| 多关联与搜索 | 页面展示全部参与确认的slot；有效中文可搜索，草稿／失效旧中文不命中；无关联的人工教材卡保留独立路径 |
| 查询规模 | 对306条掌握与当前中文搜索复测；批量解析当前状态，不能每条多出数次SQL或依赖跨请求缓存 |
| 历史边界 | 原始目标、关联、true/false、时间、收藏、笔记保留；历史呈现未知不补造；只追溯最近一次记录 |
| 导入重跑 | 不覆盖人工采用、旧快照或旧中文；预演不持久化，无按拼写自动合并 |
| PostgreSQL | 首写／过期写入、采用竞争、确认与修订竞争有真实并发用例；锁顺序一致 |
| 升级 | 空库与旧库都能迁移；真实副本对比原列；新记录有明确来源，日常库无验收账号与演示进度 |
| 浏览器 | 桌面及390px可完成词卡中文学习、教材保护、两标签页旧呈现冲突；失败不显示已保存 |

### 独立行为探针：4/4通过

脚本位于本地证据目录 `control_acceptance.py`，日志 `independent-probes.log`。使用Django隔离测试库，复用了样例构造，断言由主控单独编写：

- 撤回来源后，教材正文、关联API、通用API、学习册、词典相关教学卡、场景页面／API等8个出口均不泄漏旧中文、memo或拆分朗读文本；数据库原标注保留。
- 中文搜索命中已采用且可用版本，不命中未采用草稿、旧摘要或撤回版本。
- 教材main与secondary均实际展示；撤回次义项后显示复核提示，不能把未完成复核的集合记为掌握。
- 普通非word教材也展示其参与确认的词义引用。首次独立复现发现遗漏后，已交回修复并复测通过。

### 独立浏览器验证

主控使用Playwright独立会话、`control.sqlite3`副本和8024临时服务；没有写日常库。证据为 `browser-results.json`、`output/playwright/primary-chinese-control-*.png` 及同前缀快照。

- 390×844页面：英文词形与中文解释可读；实际页面宽度与滚动宽度均390，无横向溢出。截图已目视检查。
- 游客在中文A版标记掌握后，后台同义采用B，旧标签页提交得到409，显示“中文呈现已更新，请刷新后重新确认”；数据库learned仍true、revision仍1、所见版本仍A。
- 教材仅保存笔记后，原mastered与所见legacy记录保持，未自动补写A；随后明确勾选学习确认再保存，记录A版、revision变为2，笔记保留。
- 409请求在浏览器网络日志中属于预期冲突，不当作未知控制台错误。测试没有验证真人听音质量，也不冒称完成全部词义的中文审校。
- 主控浏览器和8024服务已关闭，含验收账号／进度的 `control.sqlite3` 已删除，截图及摘要保留。
