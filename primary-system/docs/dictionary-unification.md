# 查字查词统一展示设计

日期：2026-11-02。用户要求新导入的字典、词典与原有词库一起使用，至少统一前端。

## 数据关系与使用边界

| 资料 | 当前职责 | 统一展示方式 |
|---|---|---|
| 原有 LexicalEntry / Sense / Pronunciation 与 SourceRelease | 稳定字词和义项身份、审核过的公开资料、教学引用与证据版本 | 继续提供正式词条详情；遵守当前生效版本和原有可见条件 |
| CC-CEDICT | 简繁中文词头、分读音记录、英文原释义 | 同一次查询补充汉英参考词义；不能当成已经翻译的英汉词典 |
| CMUdict | 英语词形的 ARPAbet 读音与变体 | 同词形展示多种读音，明确音素体系；不声称是来源音频或某个义项的唯一读法 |
| Make Me a Hanzi | 汉字和部分独有部件的笔顺、字形及来源解释 | 查字时可直接看到笔顺资料，原控件可继续使用 |
| Unihan 17 | 全量汉字属性与来源字段 | 补充属性并标明版本；不覆盖正式词库当前使用的 Unihan 18 IICore |

本轮统一的是查询与阅读体验。查询时依据字形／词形聚合相关资料，**不据此宣称义项相同**。教学选择仍通过既有的义项核对、中文版本和显式采用流程完成；不自动填写 `CedictRecord.matched_sense`，不调整教材关联或场景学习目标。

## 产品约定

- `/dictionary/` 是全站查字、查词和查读音的入口，一个查询能看到各来源结果；来源浏览是次级用途。
- 汉字、中文词语、英文和成语的范围用中文说明。空查询提供清晰的浏览入口，某一来源没有结果不能误报所有来源都未收录。
- 正式词条详情直接提供同字／同词的补充资料。来源独有内容也能从统一查询进入完整详情，不要求先了解资料包名称。
- 资料探索中的语言入口收敛到查字查词；旧列表／详情地址保留兼容，返回统一入口。诗文、地理、元素和天文仍为独立学科页面。
- 释义语言、来源版本与读音体系清楚标记。英文长释义继续保留原文并分批补中文；不把导入成功或同形查询命中写成中文教学核对完成。
- 页面提供当前查询、范围、分页和返回路径。手机宽度下不横向溢出，笔顺控制可使用。

## 查询与数据保护

正式词库继续复用 `public_records` 的发布、来源启用和生效版本约束。来源资料只读取对应 `Dataset` 的 ready 状态与准确版本；旧版或未就绪记录不能经详情地址绕过。搜索不将兼容汉字折叠成另一汉字，不按大小写合并 CEDICT 原记录，不丢弃 CMU 读音变体。

采用当前页的有界查询、字段投影和批量关联。笔顺和全部属性只在必要的精确查询／详情中加载；不把全部来源 JSON 或 155 万条属性搬到列表中。来源并列展示不引入第二套词条身份或全学科学习模型。

本轮不重导数据、不自动修改学习记录，不恢复南非教材或算术事实。既有 canonical API、词条 UUID 地址与学习记录语义保持兼容。实现如确需新增索引或迁移，须在报告中明确，不能以手工数据库修改代替迁移。

## 验收口径

1. 汉字“行／木”、词语“银行／苹果”、英文“bank／light”等在一个入口查询；有来源独有内容时仍能到达。
2. 多音、多义和来源版本各自保留；“行”不能只因正式来源只列常用音而遗漏补充来源，CMU 变体不能去重为一个。
3. 未 ready、非当前版本、未公开正式来源在搜索和详情中均不可见。单独的笔顺部件 `⺀`、扩展区字符、U+ 查询不出错。
4. 分页保持查询与范围，旧地址兼容，详情返回统一查字查词；桌面及 390 像素宽度无横向溢出和浏览器错误。
5. 主控以本轮开始时的新快照核验 54 张业务表、2,517,158 行数据与 205 个托管文件；真实使用产生的并行变化单独核查，不能回滚或伪称完全不变。
6. 关联测试和 Django 检查通过，真实数据查询耗时可接受；只验证本次功能，不触发日常接龙开局。
