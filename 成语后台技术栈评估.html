00结论

推荐方案

在现有仓库旁边加一个轻量自托管服务：数据从手编 JS 迁入 SQLite，管理后台自建单页，孩子端前端只把数据来源从「JS 变量」换成「API + 离线快照」。不引入重型框架，不牺牲「双击即开」。

Node.js 24 + Hono（或 Express） + SQLite（better-sqlite3） + Drizzle ORM + 自建轻管理页
复用现有资产数据测试本就是 Node 脚本，校验逻辑直接下沉为写入时约束；现有 JS 数据可被导入脚本直接加载。
零运维负担SQLite 单文件、备份即拷文件，家庭规模（几百到几千条）毫无压力，不值得上 Postgres。
保住离线底线加一条 DB → JSON 快照导出，静态页离线打开的能力原样保留。

若「零运维、随时随地可访问」的优先级高于「数据完全在自己手里」，备选 Supabase（Postgres + 自带后台）——见 §03。桌壳方案（Tauri / Electron）因 iPad 无法使用，不推荐。

01现状盘点

成语相关功能目前是两块：成语本（idioms.html，15 类 257 条，含拼音、释义、逐字点读、典故、例句、近反义）和成语接龙（chain.html，复用成语本词库并合并补充词，共 719 条校验词库）。全部数据以手编 JS 数组形式存放在 idioms-data.js 与 chain-data.js，由家长按文件头注释手工维护。

02上数据库和后台，实际要解决什么

「加个数据库和后台」翻译成具体需求，是下面四件事——其中前两件是当下的真实痛点，后两件顺带解锁：

  1. 内容维护：从手编 1,722 行 JS 变成表单增删改查；逐字对位、近反义覆盖等规则在写入时校验，不再依赖「记得跑一遍 node test」。
  2. 词库扩容：接龙校验依赖 719 条内置词库，收录不足是体验瓶颈；入库后可批量导入外部成语词典，接龙引擎按首字查库即可，词库扩到数千条无感。
  3. 一处数据、多端读取：iPad 不再靠拷文件夹同步，改版内容所有设备即时一致。
  4. 进度同步（二期）：掌握记录、错题本迁入数据库，跨设备续学。建议一期不做，控制改动面。
Q1
服务部署在哪里？ 家里常开的 Mac / NAS（配 Tailscale 内网访问，数据不出门），或一台小 VPS。家庭自用不建议为此买云数据库。
Q2
「双击即开、完全离线」要不要保住？ 本评估默认保留（这是仓库的立身之本）。保留则必须加「DB → 静态 JSON 快照」导出链路，见 §04 架构。

03候选方案对比

方案构成契合现有资产运维多设备保离线主要代价
A · Node 自托管 推荐 Node 24 + Hono + SQLite + Drizzle + 自建管理页 高：测试逻辑与数据直接复用 低有有 管理页要自己写（约 1 天，估）
B · Supabase 备选 托管 Postgres + 自动 REST + Studio 后台 低：校验需改写为 DB 触发器 / 边缘函数 极低有弱 数据在外部服务；离线快照需另做；免费档限额随用随看
C · Python 栈 备选 FastAPI + SQLModel + SQLite + SQLAdmin 低：5 个数据测试需用 Python 重写 低有有 现有校验资产全部重写一遍
D · 桌面壳 不推荐 Tauri / Electron + SQLite 中 低无有 iPad Safari 用不了；多设备诉求直接落空

A 为什么推荐：这个项目的独特资产是「数据校验已经是 Node 代码」。选 Node，test-idioms.js 的断言几乎原样搬进写入校验；选 SQLite，是因为数据量级（几百到几千条）下 Postgres 只带来运维成本、不带来收益，而单文件库的备份、迁移、调试成本趋近于零。框架层面 Hono 与 Express 功能等价，取其轻；团队更熟哪个用哪个，不影响结论。

B 什么时候选：如果完全不想碰服务器，Supabase 的免费档（Postgres + 自动生成的 REST API + 自带管理台）开箱即用，iPad 在任何网络下都能访问。代价是数据与可用性绑在外部服务上，且「逐字对位」这类规则要么写成数据库触发器、要么放边缘函数，调试不如本地顺手。

C 什么时候选：仅当维护者更想借机转向 Python。功能上完全可行，SQLAdmin 也能快速出后台，但等于把现有最值钱的校验资产推倒重写。

D 为什么出局：主要使用终端是 iPad Safari，桌面壳无法覆盖；它保住离线的代价是放弃多设备。除非某天产品收敛为「只在一台电脑上用」，否则不值得重看。

04推荐方案与选型

层选择理由
运行时Node.js 24机器已有；现有数据测试即 Node，校验逻辑可平移。
Web 框架Hono（Express 等价可换）轻量、中间件够用；这个规模不需要 Nest 这类全家桶。
数据库SQLite · better-sqlite3单文件零配置，备份即拷文件；同步 API 性能远超需求。
数据访问Drizzle ORMschema 即代码、内置迁移、贴近 SQL；比 Prisma 轻。
管理后台自建单页（备选 AdminJS）逐字四行、近反义选择这类专属校验做成内联表单更顺手；AdminJS 可半天出全功能 CRUD 但样式与校验受限。
写入校验shared/validate 模块test-idioms.js 断言下沉共享，导入脚本与写 API 共用同一套。
认证单管理员 + session管理接口一个口令；孩子端只读公开。不上多用户体系。
部署家里 Mac/NAS + Tailscale，或小 VPS数据不出门优先；进程用 launchd 或 pm2 拉起。

架构

链路一 · 服务化（在线时）

孩子端 idioms.html现有前端小改 + 管理页 admin新写 → Hono API读写 · 校验 → SQLite · study.db单文件

链路二 · 离线兜底（保住双击即开）

SQLite -- npm run export --> idioms-snapshot.json构建产物 → 静态页离线打开行为不变

前端改动收敛在一处：idioms-app.js 现在直接读 IDIOM_UNITS 全局变量，改为「优先 fetch API，失败则读快照 JSON」。接龙引擎查词库改为调 API 的按首字查询接口，离线时退回快照内置词库。

schema 示意（Drizzle）

// drizzle/schema.ts —— 完整表清单见 §05
export const idioms = sqliteTable('idioms', {
  id:          integer('id').primaryKey({ autoIncrement: true }),
  text:        text('text').notNull().unique(),   // 唯一约束替代「全书不能重复」的人工约定
  pinyin:      text('pinyin').notNull(),
  zh:          text('zh').notNull(),
  story:       text('story'),
  source:      text('source'),
  example:     text('example').notNull(),
  categoryId:  integer('category_id').references(() => categories.id),
});

export const idiomChars = sqliteTable('idiom_chars', {
  idiomId:  integer('idiom_id').notNull().references(() => idioms.id),
  pos:      integer('pos').notNull(),            // 1–4，逐字点读按位取
  char:     text('char').notNull(),              // 「t 与位置对位」由结构本身保证
  meaning:  text('meaning').notNull(),
});

迁移四步（估）

  1. step 1 · 0.5 天建库导入一次性脚本直接 require 现有 idioms-data.js / chain-data.js 灌入 SQLite；test-idioms.js 断言搬进 shared 校验模块，导入时全量跑一遍，257 条数据当作第一次验收。
  2. step 2 · 0.5–1 天读 API分类列表、成语详情、接龙词库按首字查询（建索引）。孩子端前端切到 fetch + 快照兜底。
  3. step 3 · 0.5 天写 API成语 / 分类 CRUD；写入前跑同一套共享校验，错误按字段返回给表单。
  4. step 4 · 1 天管理页分类侧栏 + 成语表单：四字逐字行、近反义搜索选择、拼音与必填项内联提示，保存即校验。顺手做 npm run export 快照导出。

合计约 3 天（估计值，非实测；前端已高度模块化，改动面集中在数据加载一处）。

06风险与不做的事

风险与对策

  • 离线能力退化 —— 快照导出必须进发布流程（一条 npm run export），并给静态页加「快照版本号」显示，可发现数据过期。
  • 范围蔓延到进度同步 —— localStorage 逻辑一期原样不动；它和内容管理是两条独立链路。
  • SQLite 文件备份 —— 定时 sqlite3 .dump 成 SQL 文本进 git，diff 友好；二进制文件不进库。
  • 服务无人值守 —— launchd / pm2 自动拉起；服务挂了静态页照常离线可用，故障不阻塞孩子使用。

明确不做

  • PostgreSQL / MongoDB —— 几百到几千条的数据量，纯增运维成本；Mongo 还会丢掉 schema 约束。
  • Docker / 微服务 —— 单进程单文件，物理上无法更简单。
  • 多用户与权限体系 —— 一个管理口令够用；孩子端只读。
  • 进度同步（一期） —— 二期另立方案再议。
事实来源：本仓库 primary/ 目录实测 —— idioms-data.js 1,722 行 / 15 类 257 条；接龙词库 719 条；test/ 下 5 个数据测试。
